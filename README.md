# Biosignal Processor — REST API фильтрации и анализа ЭКГ (вариант 4)

Учебный проект по дисциплине «Разработка расширяемого REST API сервера для фильтрации
и анализа физиологических сигналов». Сервер принимает файл с отсчётами биосигнала,
фильтрует его, находит диагностические события и возвращает JSON с исходным и
очищенным сигналом, событиями и рассчитанными признаками.

**Вариант 4 — ЭКГ:**

| Что | Значение |
|---|---|
| Фильтрация | скользящее среднее, окно 7 отсчётов (высокочастотный мышечный тремор) + ФВЧ Баттерворта 2-го порядка 0.5 Гц (дрейф изолинии) |
| Событие | индексы начала и окончания каждого QRS-комплекса по падению энергии первой производной ниже 10 % от максимума в окрестности R-пика |
| Признаки | средняя ширина QRS в миллисекундах и максимальная пиковая амплитуда (артефактный максимум) во всём сигнале |

Стек: Python 3.14, FastAPI, NumPy, SciPy. Запуск — локально в `venv` или в Docker.

> Пошаговое руководство по развёртыванию, проверке и диагностике — в
> [RUNBOOK.md](RUNBOOK.md): команды, ожидаемый вывод, чек-лист приёмки и разбор
> типовых ошибок.

## 1. Почему Python и SciPy

- `scipy.signal.butter` и `scipy.signal.filtfilt` — эталонная реализация
  Баттерворта и фильтрации с нулевой фазой: коэффициенты и краевой паддинг не нужно
  писать вручную и проверять по битам.
- NumPy даёт векторизованные операции над массивами: кумулятивные суммы для
  скользящего среднего, `np.diff`, `np.argmax` — весь конвейер на 1250 отсчётах
  занимает единицы миллисекунд.
- FastAPI автоматически строит OpenAPI-схему и Swagger UI по аннотациям типов, а
  `UploadFile` + `python-multipart` закрывают загрузку файлов без ручного разбора
  multipart-запроса.
- Математика вынесена в `signal_processor.py` — чистые функции без импортов
  веб-фреймворка, поэтому её можно тестировать и переиспользовать отдельно от сети.

## 3. Математика

Вход: `x[0..N−1]`, частота дискретизации `fs` (по умолчанию 250 Гц). Для тестовой
записи `N = 1250`, длительность 5.0 с, `dt = 4 мс`.

Порядок этапов зафиксирован вариантом: **MA(7) → ФВЧ(0.5 Гц) → R-пики → границы
QRS → признаки**.

### 3.1 Скользящее среднее, окно 7

```
y[i] = (1 / k_i) · Σ_{j = max(0, i−3)}^{min(N−1, i+3)} x[j],   k_i = min(N−1, i+3) − max(0, i−3) + 1
```

Окно центрировано и **усекается** у границ: деление идёт на фактическое число
доступных отсчётов, нулями окно не дополняется. Иначе на первых и последних трёх
отсчётах появился бы ложный провал к нулю, который ФВЧ следующего этапа превратил
бы в краевой всплеск (полюс 0.5 Гц близок к единичной окружности и «звенит» на
любом скачке).

АЧХ усреднения по 7 отсчётам: `|H(f)| = |sin(πfw/fs) / (w·sin(πf/fs))|`:

| f, Гц | 1 | 5 | 10 | 15 | 25 | 35.7 | 50 |
|---|---|---|---|---|---|---|---|
| \|H\| | 0.999 | 0.969 | 0.878 | 0.738 | 0.374 | 0 | 0.231 |

Окно 28 мс короче QRS (~80–100 мс), поэтому комплекс «подсушивается» на 10–25 Гц,
но не деформируется; фаза у MA линейная, вершина R не смещается.

### 3.2 ФВЧ Баттерворта 2-го порядка, fc = 0.5 Гц

Билинейное преобразование с предыскажением частоты:

```
K    = tan(π·fc/fs)
norm = 1 / (1 + √2·K + K²)
b0 = norm,  b1 = −2·norm,  b2 = norm
a1 = 2·(K² − 1)·norm,  a2 = (1 − √2·K + K²)·norm

y[i] = b0·x[i] + b1·x[i−1] + b2·x[i−2] − a1·y[i−1] − a2·y[i−2]
```

Для `fs = 250`, `fc = 0.5` (`K = 0.00628326799`, `norm = 0.9911535951`):

```
b = [ 0.9911535951, −1.9823071902,  0.9911535951]
a = [ 1.0000000000, −1.9822289298,  0.9823854506]
```

АЧХ: 0.05 Гц → −40 дБ, 0.1 → −28, 0.2 → −16, 0.5 → −3, ≥2 Гц → 0 дБ. Дрейф
изолинии (0.05–0.2 Гц) давится на 16–40 дБ, QRS (10–25 Гц) проходит без искажения.

### 3.3 Почему `filtfilt`, а не один проход

Один проход БИХ-фильтра даёт частотно-зависимый фазовый сдвиг: фронты QRS смещаются
на 1–2 отсчёта, ширина искажается асимметрично. `scipy.signal.filtfilt` фильтрует
сигнал вперёд, разворачивает, фильтрует ещё раз и разворачивает обратно:

- АЧХ возводится в квадрат — эффективный порядок 2 → 4, на частоте среза −6 дБ
  вместо −3 дБ;
- фазовый набег двух проходов взаимно уничтожается, вершина R не смещается.

```python
b, a = scipy.signal.butter(2, 0.5, btype="high", fs=fs)
y = scipy.signal.filtfilt(b, a, smoothed, padlen=max(9, int(3 * fs)), padtype="even")
```

`padlen ≥ 3·fs` (1 с) обязателен: при коротком паддинге переходный процесс ФВЧ
остаётся на первых отсчётах и порождает ложный R-пик. `padtype="even"` — отражение
с реверсом без повтора крайнего отсчёта, как в эталонной реализации; при
`padtype="odd"` (значение scipy по умолчанию) среднее отфильтрованного сигнала
уезжает на −0.0101 вместо ~0.

### 3.4 Детекция R-пиков (Pan–Tompkins-подобная)

1. Центральная производная и её энергия:

   ```
   d[i] = (y[i+1] − y[i−1]) / 2,   e[i] = d[i]²
   ```

   На краях массива `d = 0`: там нет второго соседа.

2. Сглаживание энергии окном 80 мс (21 отсчёт при 250 Гц): энергия комплекса
   собирается в один бугор, одиночный шумовой отсчёт перестаёт быть кандидатом.

3. Порог:

   ```
   thr[i] = max( 0.30 · max(e в окне ±1 с),  0.05 · max(e по всему сигналу) )
   ```

   30 % от **локального** максимума, а не глобального: на эталонной записи
   амплитуды комплексов различаются по энергии в разы, и глобальные 30 % отсекли бы
   часть сокращений. Нижняя отсечка 5 % от глобального максимума защищает от
   детекции шума в тихих участках.

4. Кандидат — локальный максимум `e` выше порога, с рефрактерным периодом 200 мс
   (два R-пика не могут быть ближе). Внутри рефрактерного периода остаётся более
   сильный кандидат. Отсчёты ближе 100 мс к краям записи игнорируются: там ещё
   работает переходный процесс ФВЧ, это не физиология.

5. Уточнение вершины: `r = argmax |y|` в окне ±40 мс вокруг кандидата. Модуль —
   потому что полярность отведения не фиксирована.

### 3.5 Границы QRS по падению энергии первой производной

Для каждого R-пика `r` в окне `[r − 120 мс, r + 160 мс]`:

```
E[i]  = |y[i] − y[i−1]|                    — энергия первой производной
Es[i] = MA(E, 20 мс)                       — сглаживание (5 отсчётов при 250 Гц)
thr   = 0.10 · max(Es в окне)              — порог варианта: 10 %

onset  = последний i слева от r, где Es[i] ≥ thr (первое падение — граница)
offset = первый  i справа от r, где Es[i] <  thr (первое падение — граница)
```

Детали, без которых границы «плывут»:

- **`|Δ|`, а не `Δ²`.** Порог задан как доля от максимума, и возведение в квадрат
  меняет смысл доли: 10 % от максимума `Δ²` — это 31.6 % от максимума амплитуды
  производной, границы съезжают внутрь, ширина занижается (20–28 мс вместо 76–100).
- **Сглаживание 20 мс обязательно.** Без него одиночный шумовой отсчёт с большой
  разностью рвёт проход: 28 мс на одном комплексе против 104 мс на другом.
- **«Мёртвая зона» у вершины R.** В максимуме `|y|` производная ≈ 0, поэтому
  движение от R начинается с пропуска подряд идущих отсчётов ниже порога до первого
  отсчёта выше порога; иначе onset и offset совпали бы с R.
- **Физиологичные пределы 40–200 мс.** Если найденная ширина выходит за них (шум,
  срыв на край окна), границы симметрично расширяются/обрезаются вокруг R.
- Инвариант `onset < r ≤ offset` гарантируется конструктивно.

Ширина комплекса — интервал между границами: `width_ms = (offset − onset) / fs · 1000`.
Для границ 108–127 это 19 отсчётов = 76 мс, ровно как в эталонных измерениях.

### 3.6 Признаки

```
mean_qrs_width_ms  = (1/K) · Σ (offset_k − onset_k) / fs · 1000
max_peak_amplitude = max(y)                  — по всему сигналу, знаковый
mean_amplitude     = mean(y)
std_amplitude      = std(y)                  — по генеральной совокупности (делим на N)
heart_rate_bpm     = 60000 / mean(RR_ms)     — null, если QRS меньше двух
r_peak_count       = число найденных R-пиков
qrs_count          = число комплексов с onset < r ≤ offset
```

Все величины считаются по **отфильтрованному** сигналу: дрейф и тремор уже убраны,
амплитуды сопоставимы между комплексами и участками записи.

### Ошибки

Все ошибки валидации — HTTP 400 в едином формате:

```json
{"error": "КОД", "errorDetails": {"code": "КОД", "details": "текст"}}
```

| Код | Причина | Пример |
|---|---|---|
| `INVALID_FILE_FORMAT` | расширение не `.txt`/`.csv` | `{"error":"INVALID_FILE_FORMAT","errorDetails":{"code":"INVALID_FILE_FORMAT","details":"Неверный формат файла: разрешены только .txt и .csv"}}` |
| `EMPTY_FILE` | файл пуст или состоит из пробелов | `{"error":"EMPTY_FILE","errorDetails":{"code":"EMPTY_FILE","details":"Файл пуст или не содержит данных"}}` |
| `INVALID_SAMPLING_RATE` | `fs` вне 1…10000 | `{"error":"INVALID_SAMPLING_RATE","errorDetails":{"code":"INVALID_SAMPLING_RATE","details":"Частота дискретизации должна лежать в диапазоне 1…10000 Гц, получено 0.0"}}` |
| `INVALID_COLUMN` | колонки с таким индексом нет | `{"error":"INVALID_COLUMN","errorDetails":{"code":"INVALID_COLUMN","details":"Колонка 5 отсутствует: в строке 1 только 1 колонок(и)"}}` |
| `SIGNAL_TOO_SHORT` | меньше 10 отсчётов | `{"error":"SIGNAL_TOO_SHORT","errorDetails":{"code":"SIGNAL_TOO_SHORT","details":"Сигнал слишком короткий: 5 отсчётов, нужно не меньше 10"}}` |
| `PARSE_ERROR` | строка не является числом | `{"error":"PARSE_ERROR","errorDetails":{"code":"PARSE_ERROR","details":"Строка 1 не является числом: 'не число'"}}` |

| raw min / max | −0.65 / 2.15 (idx 742) | −0.65 / 2.15 (idx 742) | 0 |
| raw mean / std | 0.2189 / 0.6501 | 0.218944 / 0.650089 | 0 |
| Коэффициенты ФВЧ `b` | 0.9911535951, −1.9823071902, 0.9911535951 | совпадают | 0 |
| Коэффициенты ФВЧ `a` | 1, −1.9822289298, 0.9823854506 | совпадают | 0 |

**Смысловой акцент варианта.** Сырой максимум `2.15` (отсчёт 742) — не физиология,
а артефактный выброс поверх R-пика: отсчёты 739–746 равны
`1.49, 1.86, 2.10, 2.15, 2.12, 1.94, 1.54, 1.33` при локальной изолинии ≈1.05.
После MA(7) и ФВЧ выброс срезается до `0.877`, и максимум отфильтрованного сигнала
переезжает на другой комплекс — отсчёт 532 со значением `0.9956`. Именно это и
требует вариант: «максимальная пиковая амплитуда (артефактный максимум) во всём
сигнале» — по очищенному сигналу, а не по сырому.

**Единственное видимое отклонение** — `mean_amplitude`: `0.000017` против `0.0077`
в эталоне (разница `0.0077`, в пределах допуска `±0.01`). Причина — форма краевого
паддинга `filtfilt`: отражение с реверсом (`padtype="even"`) даёт на симметричном
расширении практически нулевое среднее. Остальные величины совпадают до третьего
знака.

## 9. Тестирование

### Swagger UI

1. Открыть `http://127.0.0.1:8000/docs`.
2. Выбрать `POST /analyze` → **Try it out**.
3. Задать `fs = 250`, `column = 0`.
4. В поле `file` загрузить `test_data/raw_signal.txt` → **Execute**.
5. В `Response body` проверить 6 событий и признаки из §8.

### Клиентский скрипт с графиками

```bash
python test_data/test_client.py
```

Скрипт отправляет файл на `POST /analyze`, печатает параметры записи, таблицу
признаков и первые 10 событий, затем сохраняет два PNG в `test_data/plots/`:

- `raw_signal.png` — исходный сигнал;
- `filtered_signal.png` — отфильтрованный сигнал с закрашенными зонами onset–offset
  и метками R-пиков.

Полезные опции:

```bash
python test_data/test_client.py --url http://127.0.0.1:8000 --fs 250 --column 0
python test_data/test_client.py --no-plots                 # только признаки
python test_data/test_client.py --file test_data/raw_signal.txt --output-dir /tmp/plots
```

Коды выхода: `0` — успех, `1` — транспортная ошибка (сервер недоступен, таймаут,
файл не найден), `2` — ошибка сервера (HTTP 400 или `status != "success"`).

### Проверка на синтетическом сигнале

```bash
python test_data/synthetic_ecg_generator.py --beats 10 --heart-rate 90
python test_data/test_client.py --file test_data/synthetic_signal.txt --no-plots
```

Генератор не требует NumPy и пишет файл в том же формате, что и реальная запись;
опция `--with-time-column` создаёт две колонки — удобно проверить параметр `column`.

## 11. Ограничения и допущения

1. **Частота дискретизации.** По умолчанию 250 Гц — как у тестовой записи. При
   другой реальной частоте её нужно передать в `fs`, иначе временные признаки
   (ширина QRS, RR, ЧСС) поедут пропорционально: `fs = 360` без параметра занизит
   ширину и завысит ЧСС.
2. **`max_peak_amplitude` — знаковый максимум** `max(y)`, а не модуль. На тестовой
   записи это одно и то же (`max y = max |y| = 0.9956`); для инвертированного
   отведения артефактный выброс может оказаться в минимуме. R-пики при этом
   находятся корректно: уточнение идёт по `argmax |y|`.
3. **Ширина QRS зависит от порога 10 %.** Порог задан вариантом; при сильном шуме
   границы разъезжаются. Сглаживание энергии 20 мс обязательно — без него ширина
   «прыгает» в разы на одиночных выбросах.
4. **Меньше двух QRS.** RR и ЧСС не определены — `heart_rate_bpm = null` (клиент
   печатает «не определено»), остальные признаки считаются.
5. **Многоколоночные файлы.** Задание требует поддержки «нескольких столбцов»;
   колонка выбирается параметром `column` (по умолчанию 0). Разделители: пробел,
   таб, запятая, точка с запятой.
6. **Размер ответа.** Сигнал возвращается целиком в `raw_signal` и
   `filtered_signal`, поэтому ответ растёт линейно от длины записи. Для очень
   длинных записей (миллионы отсчётов) разумно ограничить размер файла на
   прокси/веб-сервере или отдавать сигнал постранично.
7. **Только ЭКГ-морфология варианта 4.** Детектор рассчитан на QRS с частотой
   сокращений примерно 30–200 BPM; для трепетания/фибрилляции и кардиостимулятора
   пороги нужно настраивать отдельно.
8. **Нет аутентификации и ограничения частоты запросов** — учебный сервер
   предполагается запускать локально; для публикации нужен reverse proxy.
